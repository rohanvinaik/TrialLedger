# Normative verification and evidence contract

This file defines acceptance of the build, not evidence that the build already exists. Every task starts unchecked. Record actual tool versions, source/code/test hashes, entry point, request/result identities and exact limitations. Do not copy historical test counts or certificates into a current result. A schema-valid plan does not prove a clinical computation.

## V1. One loop: trace, specify, build, pin, consume

For each nontrivial change, the coordinator records a short pass brief: intended clinical question, invariant, changed producer, actual consumers, sibling paths, protected behavior, workload, unknown bindings and completion evidence. Use the following order:

1. Read relevant whole theory/design units. Restate the intended clinical decision in ordinary language. Work an actual source-backed example through the current public operation before choosing a repair. Separate what the source says, what the person must choose and what a rule computes.
2. Use fresh Serena symbol bodies and `find_referencing_symbols` before production edits. Inspect enclosing functions and downstream owners, including the parallel parser/evaluator paths. Workers receive the coordinator's traced map; use read-only Aider map/AST and whole-unit reads for orientation. No search snippets as semantic evidence, and no per-worker heavy language-server multiplication.
3. Author direct-call positive and MUST-NOT tests from intent, before relying on generated characterization. Name each protected degree of freedom. Add independent mathematical oracles where claiming exhaustive arithmetic/sets/graphs. SICP-style pure decisions over bounded typed data must return named outcomes and have small explicit contracts; transport, file writes and source acquisition stay at boundaries.
4. Implement the owned slice, run relevant tests, pinned lint/format checks and type analysis in the project's declared environment. Inspect type findings instead of suppressing broadly. A clean type check is neither a logical proof nor a substitute for behavioral tests.
5. Follow the current Detective/Wesker protocol literally, then verify the production path consumes the pinned signal with unchanged support. Run genuine CrossHair contracts with `--report_all`; retain Confirmed/Not confirmed/no-checkable-contract distinctions.
6. Exercise the slice through CLI and initialized MCP, including malformed/boundary cases and revision/export when relevant. Record per-class identified, correctly abstained and wrong outcomes. Conduct a different-category clinical walkthrough before closing a substantial integration wave.

No trace based solely on imports, symbol existence or unit tests counts as wiring verification. No tool score can authorize a changed clinical premise. If the tool is unavailable, say which instrument is missing and retain that gate as incomplete; do not fabricate an equivalent certificate.

## V3. Independent oracles and algebraic contracts

- **Intervals:** an independent endpoint-cell oracle enumerates all supplied rational endpoints, singleton points and open cells between them, with unbounded outer cells. Compare membership/set operations on every cell, not only integer days. Check permutation, duplicate and union idempotence; widening C cannot reduce feasibility or worsen coverage; nominal/window/support remain separate.
- **Policies:** a small reference breadth-first graph explorer over a separately constructed finite transition relation. Compare reachability, gaps, overlaps, prohibition/invariant witnesses and all-path termination on tiny models. Reorder transitions and duplicate equivalent support without changing truth. Terminal, dead-end and cycle cases are mandatory.
- **Binomial:** for small n, enumerate all 2^n binary outcome vectors, compute their independent exact product probabilities and compare the rejection event to the production tail. Do not call the production mass/tail helper from the oracle. Check normalization, endpoint probabilities and monotonicity in k and p.
- **Support/bindings:** metamorphic changes in scope, source edition, polarity, units, condition, status and origin must affect exactly their declared consumers. Preserve both mathematical and admission results. Independent-source counts cannot increase when duplicating one projection.

Exercise hypothetical-frame leakage explicitly: local draft assumptions can enable conditional checks, but proposed external source interpretations and unrelated unknown bindings cannot be lifted with them. Passing that local frame into an unconditional consumer must be refused or retain the conditional gate.

Property tests quantify their domain and assumptions. CrossHair is useful on pure finite/rational helpers with checkable pre/postconditions; it must not claim proof of unrepresented clinical semantics.

## V6. Clinical model-run walkthroughs

This is an LLM model action, not a literal CI assertion of clinical truth. Perform it after every substantial integration wave, not merely at final release. Before gathering, state a sane clinical-development task and the required information. Use a bounded real NIH pull; choose a recorded random subset from a declared eligible pool without discarding awkward records. Retain search, pool accounting, seed/selection rule, NCT IDs, timestamps and fingerprints. If the pool is too small or lacks relevant data, document it and select another explicit scope; do not manufacture source facts.

Minimum rotation (the clinical thresholds remain attributed simulated choices, not recommendations):

| Integration wave | Distinct walkthrough and semantic stress |
|---|---|
| Objects/schedule/dependencies | Phase 2 neurological functional-outcome study: baseline, repeated measures, nominal versus permitted visits and collection after treatment stop |
| Finite policy | Phase 1 haematology dose-escalation/safety study: cohort versus participant actions, DLT observation versus longer safety horizon, explicitly open efficacy section |
| Exact efficacy | Phase 2 infectious-disease binary-response study: fixed-n assumptions and critical count, alternative planning choices and exact probabilities |
| Managed alternatives/public lifecycle | Phase 3 renal time-to-event outcomes study: external survival method preserved uncomputed, endpoint ascertainment and competing collection plans |
| Final cold handoff | A further disease/design combination such as an immune-disease withdrawal or paediatric cluster design, with a phase-appropriate query; multi-stage scope and unsupported-method honesty |

For each, work like a clinical-development lead: Who is measured? Which definition/edition? What would happen after discontinuation? Which visit can happen when? What data are prerequisites? Which rule selects an action and over which declared variables? What remains the person's choice? Which evidence would resolve it? Deliberately try one plausible wrong design and one warranted repair. Do not merely rename a prior fixture.

Report what was obtained, what was computed, what was conditional, what abstained and what was wrong. Judge output coherence/noise against the actual question: missing useful findings, repetitive raw JSON and unexplained statuses are defects to trace upstream. Do not delete evidence to make the output appear cleaner. A simulated clinician does not authenticate human confirmation or establish clinical generality. These walks are counterexample probes across varied structures, not a universal validation certificate.
