# Proposal

## Why

The baseline and clinical-user audits found useful information retained but obstructed, unconsumed or
poorly explained between source acquisition, symbolic operations and the clinical decision list. Repair
these handoffs while preserving source fidelity, conditional warrants and exact abstention.

## What Changes

- Scope the broad-query guard to expected NIH acquisition size and request complexity; remove repeated
  retained-source JSON size as a reason to reject ordinary local revision. Preserve genuine solver/output limits.
- Align callable reasoning operations, focused discovery and emitted MCP schemas/descriptions.
- Retain literal local eligibility heading context and source offsets beside individual workbook/JSON rows.
- Expose per-input coordinate consumption/effect separately from premise admission, without inventing
  progression or treating previously treated as synonymous with post-progression.
- Explain competing-frame answer/scope differences in aggregate results and downstream consumers while
  preserving correct UNDETERMINED and proposed standing.
- Reuse bounded record/address access through CLI; document name search and reduce typed-input preparation
  through strict constructors/examples without adding clinical phrase recognizers.
- Keep corpus frequency thresholds explicitly descriptive; preserve exact small-set counts and distinct
  class-association support. Validate Python deviation inputs before unknown codes can assert a deviation.
- Make declared confirmation/choice attribution inspectable without claiming authenticated consent or
  source truth. Reconcile README, assistant guidance and canonical component inventories.

## Capabilities

### New Capabilities

None; extend the existing reporting and symbolic capabilities.

### Modified Capabilities

- `registry-reporting`: acquisition safeguards, literal passage context and reusable bounded CLI evidence access.
- `symbolic-trial-design`: truthful discovery, local reasoning budgets, input effect traces, conditional
  contrast explanations, typed preparation and explicit attribution/threshold boundaries.

## Impact

Owners include request/ingest/steps/operate, landscape/readout/report replay, CLI/MCP, coordinate admission,
interpretations/result semantics and the relevant discovery guides. Additive output fields retain complete
source text, offsets and existing clinical results. Named admission errors intentionally reject malformed
utility inputs previously accepted accidentally. Existing retained reports need explicit replay compatibility.
No new model, external service, clinical equivalence rule or whole protocol writer is introduced.
