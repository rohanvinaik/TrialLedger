# Clinical review export: wiring and verification

`reason-export` and MCP `reason_export` call one `clinical_export.export_review` owner. The renderer reads verified immutable request/response artifacts, uses `clinical_answers.project` for effective outcomes, and preserves canonical session questions, labels and choices. It introduces no clinical admission or recommendation rules. Refused related operations pass their original problems to the same projection owner.

The new outer output folder is created exclusively only after staging and complete cell/link read-back. One directory rename publishes its `review` child. Existing caller files are never overwritten. The export contains the decision workbook, Markdown list, complete byte-exact artifact copies, a hash manifest, and optional unchanged source JSON/workbook copies. Source association is explicitly caller-supplied; it establishes no population identity or comparability.

The primary decision and option views use the existing codes' clinical wording alongside the raw codes. Only the existing `feasible` + `UNDETERMINED` + sole `undecided_by_constraints` outcome receives “the represented proposition is allowed but not required” wording. Unconfirmed readings, unresolved scope, computation limits, inconsistent criteria and unknown codes keep their own open remedies. Caller-declared and simulated origins remain visible; none authenticates a human exchange.

`baseline_tables` and its existing `group_code` own source table shape and local group resolution. The comparative view places a category across unique exact local group IDs. Duplicate measurements remain separate objects rather than a selected value or a sum. Unplaced values stay explicit. The long view preserves every measurement, population state and all matching class/measure/module denominators. Total groups are never added to their arms.

The existing `cells.cell_text_state` owns XML and UTF-16 representability; carriage returns are replaced only in the validation input, with actual content preserved via XML character references. `cells.cell_number_state` owns unchanged numeric representability. Formula-like strings stay literal. Unrepresentable values receive a clickable canonical reference instead of truncation. Source strings are never numerically coerced. Writing timestamps in the newly rendered review workbook are normalized; identical complete inputs produce identical files. Source workbooks remain untouched.

A real CLI HFrEF export exposed a premise-container bug: `design_bounds.result.premises` is an object rather than the managed session's list. The fixed renderer preserves that complete object at its canonical address, and real public `design_bounds` and `signals` examples guard both shapes. The final HFrEF handoff includes six separate analyses without assigning them to decisions.

The authored suite checks actual saved workbook values and hyperlinks, canonical content, source-copy preservation, zero/false/null/empty distinctions, numeric precision, CRLF, UTF-16 astral boundaries, forbidden XML characters, duplicates, all denominator scopes, refusals, unknown statuses and no-overwrite publication. The frozen authored suite has 43 passing cases, including a direct MUST-NOT against deleting CR to make an overflow fit. Detective's pure decision pins and CrossHair results are recorded separately in the final proof receipt; I/O renderers have durability/read-back tests, not a blanket mutation-completeness claim.
