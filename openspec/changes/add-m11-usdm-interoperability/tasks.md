# Tasks

All tasks are planned, not implemented. [Design](design.md) defines the verification obligations for every package. M1/M2/M3 are release cuts, not due dates; GitHub package IDs are stable links to the same work.

## 1. IO-01 — Profile, fixtures and contracts (M1)

- [ ] 1.1 Pin USDM 4.0.0, final M11, terminology/crosswalk/rule artifacts and licences; verify exact hashes, version differences and externally authored fixture provenance in a manifest.
- [ ] 1.2 Freeze source, identity, mapping, warrant and public request/result contracts; verify valid/malformed examples, an explicit compatibility matrix and independent acceptance cases; re-estimate against the resulting gaps.

## 2. IO-02 — Protocol sources (M1; after IO-01)

- [ ] 2.1 Add versioned protocol-document retention, exact addresses and immutable identity; verify null/empty/malformed/duplicate IDs, wrong editions, digest mismatch, bounded continuation and served-root isolation through CLI/MCP.
- [ ] 2.2 Connect protocol origins and source bindings without rewriting old artifacts; verify NIH source/report and session replay compatibility, authored two-sign cases, scoped pins and a rotating clinical walkthrough; update source documentation.

## 3. IO-03 — Import and scoped projections (M1; after IO-01/02)

- [ ] 3.1 Add explicit population/arm/epoch, endpoint/estimand and fixed-visit mappings; verify against independent source-to-target oracles, codebook definitions and exact support/standing/scope traces.
- [ ] 3.2 Add preservation/mapping/conformance/analysis coverage and proposed interpretation frames; verify unsupported graphs, textual conditions, calendar durations, source conflicts and independent surviving facts; pin pure decisions and document a different-category clinical walk.

## 4. IO-04 — Public clinical lifecycle (M1; after IO-03)

- [ ] 4.1 Wire discovery, preparation, source access, retention and computation through shared CLI/MCP; verify a cold operator needs no private imports or whole-document copying and bounded replies link to all omitted detail.
- [ ] 4.2 Trace each claim into decision view, revision and evidence-linked Markdown/workbook; verify a consequential edit, conditional applicability, an unrun check and proposed support, with parity, pins, updated guidance and a fresh clinical walkthrough. Publish the M1 profile/receipt.

## 5. IO-05 — Bidirectional exchange (M2; after IO-03/04)

- [ ] 5.1 Implement native-graph preservation, identity maps and explicit supported edit write-back; verify unedited semantic round trips and edited reference/version correctness against independent fixtures, including unknown extensions/narrative content.
- [ ] 5.2 Deliver detached warrants and optional documented extensions; verify missing/stripped manifests, stale adoption, edition collision and unsupported edit refusal through fresh import/revision/export, with pins, guidance and another clinical walk. Publish the M2 profile/receipt.

## 6. IO-06 — M11 content and assembly (M3; after IO-01/05)

- [ ] 6.1 Implement the pinned M11 element crosswalk, conditional coverage and independent terminology/business-rule results; verify required/optional/unknown-applicability cases and that placeholders never count as complete content.
- [ ] 6.2 Assemble supplied content into the reviewable M11 structure and clinical views; verify preserved wording, reusable content, source links and visible unchecked sections by rendering and cold clinical handoff, with scoped pins and documentation.

## 7. IO-07 — Broader study graphs (M3; after IO-03/05)

- [ ] 7.1 Extend declared mappings for nested/branching/repeated timelines and amendment/epoch/arm relations; verify external graphs, event-ended repetition, scope separation and explicit unsupported analysis without silent finite truncation or new statistical claims.
- [ ] 7.2 Exercise supported broader profiles through CLI/MCP, revision and exchange; verify unchanged unsupported content, public coverage limits and cold clinical cases across phases/diseases/structures, with independent tests, scoped pins and updated profile documentation.

## 8. IO-08 — Integrated release acceptance (M3; after IO-04/05/06/07)

- [ ] 8.1 Independently audit external fixtures, edit conservation, schema/reference/terminology/business rules and every producer-to-consumer edge; verify CLI/MCP/export agreement, historical replay and a final cold handoff; repair and retest concrete defects.
- [ ] 8.2 Freeze the final code/test/rule basis and run serialized Detective/contract audits and required gates; verify a per-target proof/limitation ledger, honest QC freshness and compatibility claims, reconciled docs/specs and a linked M3 release packet. Close issues/milestones only for the accepted scope actually demonstrated.

## Workflow follow-up

- Archive the OpenSpec change only after implementation and the declared release acceptance are complete; planning artifacts alone do not satisfy this.
- Partner-specific connectors and future standard versions require separately scoped changes and fresh compatibility evidence.
