## Ownership and production path

`numeric_evidence` owns finite count equations and typed witness expressions; `graph_evidence` owns exact
interval closure, regimen composition and directional relations; `dependency_evidence` owns explicit adopted
prerequisites. Their fixed `evaluate`/`check` interfaces return code, value, blockers and a rule version.
`signals` owns support standing and structural predicate substitution. It loads only a fixed module map.
`service` validates wrappers and constructs typed objects; `signals_guide` and `bounds_guide` expose contracts.
`design_bounds` owns independent witness checks, joint per-signal candidate claims and common consequences.
The existing formula compiler/evaluator remains the single owner of participant logic.

Both CLI `_reason` and MCP `_reason` call the same public `layer2.run -> service.run` dispatch. Standalone
`signals` calls `_signals -> signals.evaluate -> operator.evaluate`. Design resolution calls
`_design_bounds`, evaluates source signals once, then resolves a derived observation through
`signals.derived_witness -> expression_body`. Its interval reaches `Observation`; only the guaranteed lower
count reaches `witness_support`. Both acceptance and rejection use `entail.eligibility_witness`, which reuses
`decide`, the existing formula compiler and finite evaluator. Candidate `signal_claims` are grouped by signal
before `operator.check`, so their joint constraints reach `candidate_state`. Eliminations and query decisions
feed `common_result`, including eliminations' weakest standing. The assistant uses returned results in the
README's decision-list/revision workflow. No automatic background session manager is claimed.

Serena references verified both public callers, the signal evaluation/derivation consumers and the core
composition consumer. A real CLI runtime trace on the retained two-marginal IPASS request observed one
`overlap_bounds`, one signal evaluation, one derived-witness/substitution, two eligibility-witness checks,
two witness support/verdict checks, one design composition and one common-consequence reduction. The full
local call inventory is `source-trace.json` in the installation packet named below. This observes that
workload's execution, not a runtime-efficiency gain.
